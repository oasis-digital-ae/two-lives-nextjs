# Two Lives Theory — Next.js

A Next.js (App Router) port of the static Two Lives Theory site that keeps the
design pixel-for-pixel. It does that by **not** rebuilding the design: the
static site's compiled stylesheet and its jQuery/Swiper/anime.js stack are
shipped unchanged, and only the page markup is turned into JSX.

## How it works

| Static site | Here |
|---|---|
| `css/site.min.css` | `public/css/site.min.css`, linked as a plain render-blocking stylesheet from `app/layout.tsx` (not imported through Next's CSS pipeline, so nothing gets rewritten) |
| `js/jquery.js` + `vendors.min.js` + `main.min.js` + `app.min.js` + inline scripts | `public/js/site.js`, one bundle built by `tools/build-theme-js.mjs`, loaded after hydration with `next/script` |
| `index.html` body | `app/page.tsx`, generated by `tools/convert-html.mjs` |
| `<head>` tags | the `metadata` export in each page (also generated) |
| `/.netlify/images?url=...` image URLs | unchanged. Netlify's Image CDN answers them in production; in `next dev` a rewrite in `next.config.ts` serves the original file instead |
| fonts, images, `img/`, `subtitles/` | copied into `public/` (only the files the pages reference) |

Why the bundle replays events: the theme registers dozens of `DOMContentLoaded`
and `window.load` handlers. In Next the bundle runs after both have fired, so
`tools/theme-shim.js` captures those registrations while the bundle executes
and fires them afterwards, in the order a browser would.

Why JSX is generated with an HTML5 parser (parse5): React compares its server
HTML with the DOM the browser builds. Converting the source text naively leaves
differences (implicit tag closing, a leading BOM, `selected` on `<option>`) that
show up as hydration mismatches. Parsing the way a browser does avoids that.

## Porting another page

```bash
# 1. markup -> JSX (+ metadata export). Component name is the last argument.
node tools/convert-html.mjs ../two-lives/about.html app/about/page.tsx /tmp/about-report.json AboutPage

# 2. read the report: inline scripts it skipped, !important inline styles,
#    anything under `warnings`. Inline scripts go into tools/ and the bundle.

# 3. copy any images the page references that are not in public/ yet.

# 4. body classes: the static pages set per-page classes on <body>
#    (the homepage uses "custom-cursor index-page"). Those currently live in
#    app/layout.tsx and will need a per-route mechanism once more pages exist.
```

If the static site's JavaScript changes, rebuild the bundle:

```bash
node tools/build-theme-js.mjs ../two-lives
```

## Develop

```bash
npm install
npm run dev      # http://localhost:3000
npm run build
```

Known and pre-existing: the theme's Swiper `slideChange` handler throws
`Cannot read properties of undefined (reading 'querySelectorAll')` once per
carousel on the static site too. Harmless, but noisy in the console.

## Status

- `/` ported and checked against production: every section's position and
  height match at desktop and phone widths, through the same CSS and scripts.
